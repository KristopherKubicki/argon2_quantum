# Quantum Speedbump overview

The project began as an experiment combining Argon2 and quantum-generated bytes.
Review found that the original circuit generates randomness but does not enforce
a quantum work factor, and the expiring cloud cache made hashes unverifiable.

The v0.2 release candidate uses durable Argon2id/HMAC password records. Local keys
are stored outside the user database; AWS uses a non-exportable KMS HMAC key.
This provides a concrete additional boundary for database-only compromise when
the attacker lacks protected-key/oracle access. It is not reversible encryption
or a post-quantum scheme. Optional quantum enrollment entropy remains experimental.

New records include salt, work parameters, version and key ID. Verification needs
no QPU or Redis. Rotation keeps old keys available and replaces records after
successful login. Legacy local records have an explicit migration path; missing
legacy cloud quantum bytes cannot be recovered by re-running the circuit.
